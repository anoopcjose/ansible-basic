1. Generate a root key.
==============================================

openssl genrsa -out "root_reshmamjoby_in.key" 4096

++++++++++++++++++++++++++++++++++++++++++++++

2. Generate a CSR using the root key.
==============================================

openssl req \
-new -key root_reshmamjoby_in.key \
-out root_reshmamjoby_in.csr -sha256 \
-subj '/C=IN/ST=KL/L=Cochin/O=AJ/CN=*.reshmamjoby.in'

++++++++++++++++++++++++++++++++++++++++++++++

3. Configure the root CA. Edit a new file called root-ca.cnf and paste the following contents into it. 
This constrains the root CA to only sign leaf certificates and not intermediate CAs.
==============================================

vim root-ca.cnf

[root_ca]
basicConstraints = critical,CA:TRUE,pathlen:1
keyUsage = critical, nonRepudiation, cRLSign, keyCertSign
subjectKeyIdentifier=hash

++++++++++++++++++++++++++++++++++++++++++++++

4. Sign the certificate.
==============================================

openssl x509 -req -days 365 -in "root_reshmamjoby_in.csr" \
-signkey "root_reshmamjoby_in.key"  -sha256 -out "root_reshmamjoby_in.crt" \
-extfile "root-ca.cnf" -extensions \
root_ca
++++++++++++++++++++++++++++++++++++++++++++++

5. Generate the site key.
==============================================

openssl genrsa -out "docker_reshmamjoby_in.key" 4096
++++++++++++++++++++++++++++++++++++++++++++++

6. Generate the site certificate and sign it with the site key.
==============================================

openssl req -new -key "docker_reshmamjoby_in.key" -out "docker_reshmamjoby_in.csr" -sha256 \
-subj '/C=IN/ST=KL/L=Cochin/O=AJ/CN=*.reshmamjoby.in'
++++++++++++++++++++++++++++++++++++++++++++++

7. Configure the site certificate. Edit a new file called docker_reshmamjoby_in.cnf and paste the following contents into it.
This constrains the site certificate so that it can only be used to authenticate a server and can’t be used to sign certificates.
==============================================
vim docker_reshmamjoby_in.cnf

[server]
authorityKeyIdentifier=keyid,issuer
basicConstraints = critical,CA:FALSE
extendedKeyUsage=serverAuth
keyUsage = critical, digitalSignature, keyEncipherment
subjectAltName = DNS:*.reshmamjoby.in
subjectKeyIdentifier=hash

++++++++++++++++++++++++++++++++++++++++++++++

8. Sign the site certificate.
==============================================

openssl x509 -req -days 750 -in "docker_reshmamjoby_in.csr" -sha256 \
-CA "root_reshmamjoby_in.crt" -CAkey "root_reshmamjoby_in.key" -CAcreateserial \
-out "docker_reshmamjoby_in.crt" -extfile "docker_reshmamjoby_in.cnf" -extensions server

++++++++++++++++++++++++++++++++++++++++++++++

9. The site.csr and site.cnf files are not needed by the Nginx service, but you need them if you want to generate a new site certificate. Protect the root-ca.key file.
==============================================

Configure the Nginx container
==============================================
1. Produce a very basic Nginx configuration that serves static files over HTTPS. The TLS certificate and key are stored as Docker secrets so that they can be rotated easily.

In the current directory, create a new file called default_reshmamjoby_in.conf  with the following contents:
==============================================
vim default_reshmamjoby_in.conf 

server {
        listen 443 ssl;
        listen [::]:443;

		ssl_certificate             /etc/nginx/conf.d/docker_reshmamjoby_in.crt;
		ssl_certificate_key     /etc/nginx/conf.d/docker_reshmamjoby_in.key;

		root	/var/www/html;
        index index.html index.htm index.php;

        server_name *.reshmamjoby.in;

        location / {
                proxy_pass http://*.reshmamjoby.in;
                proxy_set_header Host $host;
                proxy_set_header X-Real-IP $remote_addr;
                proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
                proxy_set_header X-Forwarded-Proto $scheme;
        }
}

server {
        listen 443 ssl;
        listen [::]:443;
		
        server_name frontend.reshmamjoby.in;

        location / {
                proxy_pass http://frontend.reshmamjoby.in;
                proxy_set_header Host $host;
                proxy_set_header X-Real-IP $remote_addr;
                proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
                proxy_set_header X-Forwarded-Proto $scheme;
        }
}

server {
        listen 443 ssl;
        listen [::]:443;
		
        server_name api.reshmamjoby.in;

        location / {
                proxy_pass http://api.reshmamjoby.in;
                proxy_set_header Host $host;
                proxy_set_header X-Real-IP $remote_addr;
                proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
                proxy_set_header X-Forwarded-Proto $scheme;
        }
}
++++++++++++++++++++++++++++++++++++++++++++++

2. Create two secrets, representing the key and the certificate. You can store any file as a secret as long as it is smaller than 500 KB. This allows you to decouple the key and certificate from the services that use them. In these examples, the secret name and the file name are the same.

==============================================

docker secret create docker_reshmamjoby_in.key docker_reshmamjoby_in.key

docker secret create docker_reshmamjoby_in.crt docker_reshmamjoby_in.crt

++++++++++++++++++++++++++++++++++++++++++++++

=======================
3. Save the docker_reshmamjoby_in.conf file in a Docker config. The first parameter is the name of the config, and the second parameter is the file to read it from.
==============================================

docker config create docker_reshmamjoby_in.conf docker_reshmamjoby_in.conf

++++++++++++++++++++++++++++++++++++++++++++++

List the configs:
==============================================

docker config ls
 
++++++++++++++++++++++++++++++++++++++++++++++

4. Create a service that runs Nginx and has access to the two secrets and the config. Set the mode to 0440 so that the file is only readable by its owner and that owner’s group, not the world.

==============================================

docker service create \
--name nginx \
--secret docker_reshmamjoby_in.key \
--secret docker_reshmamjoby_in.crt \
--config source=docker_reshmamjoby_in.conf,target=/etc/nginx/conf.d/docker_reshmamjoby_in.conf,mode=0440 \
--publish published=3000,target=443 \
nginx:latest \
sh -c "exec nginx -g 'daemon off;'"

++++++++++++++++++++++++++++++++++++++++++++++

Within the running containers, the following three files now exist:
==============================================

    /run/secrets/docker_reshmamjoby_in.key
    /run/secrets/docker_reshmamjoby_in.crt
    /etc/nginx/conf.d/docker_reshmamjoby_in.conf

++++++++++++++++++++++++++++++++++++++++++++++

5. Verify that the Nginx service is running.

==============================================
docker service ls

docker service ps nginx

++++++++++++++++++++++++++++++++++++++++++++++

Verify that the service is operational: you can reach the Nginx server, and that the correct TLS certificate is being used.
==============================================
curl --cacert root_reshmamjoby_in.crt https://0.0.0.0:3000
 
openssl s_client -connect 0.0.0.0:3000 -CAfile root_reshmamjoby_in.crt
